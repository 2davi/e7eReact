# 0424 보강

## 형상 관리 프로토콜

- 형상 관리: SW Configuration Management
  형상관리의 대상은 개발환경 뿐 (빌드/실행환경은 gitignore 대상)
- 버전 관리: Version Control System

- CVCS: Centralized Version Control System, Subversion
  중앙 집중화된 형상 관리 시스템 => 내가 하루동안 작업한 이력을 히스토리 상태로 서버에 저장
  하나뿐인 중앙 서버에 문제가 생기면 작업사항 몽땅 날아감.

- DVCS: Distributed Version Control System
  분산형...
  나와 내 동료의 컴퓨터에도 서버의 히스토리가 동일하게 저장되어 있음
  GIT과 SVN의 차이는 repository끼리의 동기화 방식에 있다.

- GIT에서 해야하는 설정...
  1. 커밋하면 내 레포에 저장됨
  2. 커밋한 내 히스토리를 서버로 push한다.
  3. 동료 컴퓨터에서는 서버로부터 모든 상태 설정 정보를 땡겨온다(pull).
  나도 저장소를 갖고 있고 서버에도 저장소가 있어서 두 저장소를 동기화해야 한다.

- GIT != GITHUB.

- branch??

- 레포 안에서 작업 : 워킹 영역에 머무는 상태
- add : 작업결과(생성||수정사항) 스테이징 영역에 올리기 == 인덱싱만 한 상태
- commit: 히스토리 만들기
  commit ID 옆에 따라다니는 Head Pointer (HEAD -> master)
  현 상태 표시.

- 분산저장의 개념, git에서 3개 (작업, 인덱싱, 커밋)영역으로 나누는 매커니즘, 적절한 ignore 설정을 놓치면 어디서 충돌 나도 모른다

- 시작할 때 ;: Pull부터
- 퇴근할 때 ;: add, commit, push
